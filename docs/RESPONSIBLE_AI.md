# Responsible AI note

ModelPassport uses AI agents to prepare model risk evidence. A human reviews and signs every stage, and every claim and number the agents write is checked by code.

## Data used

* Public or synthetic data only, never personal data. M001 uses the UCI Default of Credit Card Clients dataset and M002 the UCI Statlog German Credit dataset, both under CC BY 4.0. M003 uses synthetic data from a seeded script; M004 has no data.
* Model owners appear as role titles such as "Head of Cards Credit Risk", never as names.
* Sex and age band are never model inputs. They are kept in the data only so that outcomes can be tested for fairness.

## Privacy and security

* Keys live only in a local `.env` file, which is never committed. The LLM key is never logged, printed or written to a file; settings hide it even when printed.
* Prompts carry only the model's own files and small extracts. The agents read files through a safe reader that allows only the model estate and the run outputs, and always blocks the evaluation answer keys.
* The default LLM is a free tier endpoint, which may use prompts to improve the provider's products. That is acceptable here because only public data and our own sample code are sent. A bank would run the same pipeline against a private deployment in its own cloud tenant, by changing the endpoint settings.

## Human oversight and independence

* Agents never approve their own work. Each of the five stages pauses for a human approve or reject decision, with the reviewer, role, comment and review time recorded.
* Validation is independent of development in three ways: validation_lab computes every number with no LLM; the validator agent is a separate agent that sees only the results, never the other agents' traces, and can run on a different model; and the person who approved redevelopment cannot approve validation (the API refuses it).
* Automatic approvals exist only for seeding demo runs. They use named demo reviewers, are marked automatic in the audit trail and are left out of the human review figures.

## No invented facts

* Every sentence the documentation agent writes is a claim with file and line evidence. Code checks each quote in the cited file. Claims that fail stay visible as unverified, and questions the files cannot answer are marked "SME input needed" for the model owner.
* The validation narrative may only use numbers that exist in the computed results. Code checks every number; one rewrite is allowed, and any number that still fails is listed in the report.
* Failures are shown, never hidden: a parity that is not reached, a failed service call or an unrecorded LLM reply stops the stage with its error.

## Fairness

validation_lab tests outcomes by sex and age band on the holdout sample, with approval as the favourable outcome: the demographic parity ratio (lowest group approval rate over the highest), the equal opportunity difference (largest gap in approval rate among customers who did not default) and the equalized odds difference (the larger of that gap and the gap among customers who defaulted). The limits (ratio 0.80 or more, gaps up to 0.05 for green) are illustrative defaults, not regulatory limits, and the report says so.

## Safe execution and traceability

* Code generated by the rebuild agents is checked and run in an isolated process with a time limit inside redev_engine, never inside factory_core.
* Every LLM call (step, model, prompt hash, tokens, time, cached or not), service call, artifact write, stage change and gate decision is an event in a hash chained audit trail. Changing, inserting or removing an event breaks the chain, and the API reports it.
* Every LLM reply is cached with its prompt hash, so a recorded run can be replayed and inspected without calling a provider.

## Models the product calls at run time

* factory_core: the discovery, documentation, document drift and validator agents call one OpenAI compatible endpoint (default: a Gemini Flash model through Google AI Studio), set by `LLM_BASE_URL` and `LLM_MODEL`. The validator agent can use a different model through `LLM_MODEL_VALIDATOR`. Temperature is 0.
* redev_engine: code analysis, translation, test writing and mismatch diagnosis use the same kind of endpoint.
* validation_lab: no LLM.
* The validation report names the model that wrote its narrative.

## Limitations

* Parity proves equivalence on the tested records, not on every possible input.
* The holdout sample is random, not out of time, and monitoring batches are simulated.
* The Taiwan (2005) and German (1994) data are not UK portfolios.
* The SS1/23 matrix is a simplified team mapping, not a regulatory assessment.
* Generated documents, narratives and reports are drafts for expert review.
